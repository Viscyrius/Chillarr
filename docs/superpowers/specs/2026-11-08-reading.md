# Reading: manga, manhua and books (branch `books`)

Goal: a Read tab that finds, downloads and reads manga, manhua/webtoons and
books, with full-quality pages, on the PC window, phones and (for comics) the TV.
Everything lives in Jellyfin's libraries; no extra app the user ever opens.
Covers issue #8.

**Fused, like Radarr (user, 2026-11-08):** Suwayomi is a part of Chillarr, not
a second app. Installed by onboarding, started/stopped/restarted by Chillarr,
no window, no tray icon, no browser tab, settings written by Chillarr only,
shown in Settings > Status as one line like Radarr. The user only ever sees
Chillarr. Page serving, scan, read state and clean-up are Rust (`read.rs`).

## Pieces

| Piece | What | Why |
|---|---|---|
| Jellyfin **Bookshelf** plugin | `Manga`, `Manhua`, `Books` libraries (type books) | Items, covers, per-user progress (`UserData.PlaybackPositionTicks` = page), works with every profile |
| **Suwayomi-Server** (Windows bundle, own JRE) | Downloads chapters as CBZ into the Manga/Manhua folders | Sonarr-for-manga: follows a series, grabs new chapters. Runs hidden like Radarr; GraphQL on 127.0.0.1:4567 |
| **Prowlarr** (have it) | Book search (categories 7000/7020 ebook) -> qBittorrent category `books` -> import into `Books` | No Python/LazyLibrarian install on a friend's PC; `downloads_home` + orphan rules cover it |
| **Chillarr reader** (new, `src/js/reader/`) | Three modes, see below | jellyfin-web's comic reader is one-page, no vertical scroll: wrong for webtoons |
| `read.rs` (bridge routes) | `/read/<item>/manifest`, `/read/<item>/page/<n>?w=` | Pages come out of the CBZ server-side: works on Chrome 53 (no DecompressionStream), original bytes by default |

## Quality rules (the user's priority)

- Pages are served **byte-for-byte from the archive** (no re-encode) unless the
  device asks for a width; a downscale is only offered on phones over mobile
  data and is never upscaled. Lossless PNG/WebP stays as is.
- Source choice: per series, Chillarr asks Suwayomi for every installed source
  that has it and prefers, in order: official/scanlator group source, highest
  page width measured on chapter 1 (sample 3 pages), most chapters, latest
  update. The pick is shown ("from Asura, 1600px") and can be changed.
- Webtoon strips: no gaps, no per-image scaling seams (images laid at
  `width:100%` in one column, decoded ahead 3 screens, `image-rendering:auto`).
- Books: EPUB rendered as HTML (fonts embedded in the book kept), PDF via the
  browser's own viewer on PC/phone.

## Reader modes

1. **Manga** (paged, right-to-left, double-page spread on wide screens,
   tap/arrow/swipe zones, preload next 4 pages, zoom + pan).
2. **Webtoon / manhua** (continuous vertical scroll, chapter auto-continues,
   remembers position by image + offset).
3. **Book** (EPUB: paginated columns, font size, line height, night/sepia,
   tap to turn; PDF on PC/phone).

Mode default from metadata: AniList `countryOfOrigin` KR/CN or format
"webtoon" -> Webtoon, JP -> Manga; per-series override saved per profile.
TV: Manga and Webtoon with remote keys; Books hidden on TV.

## Discovery (Read tab)

Rows from AniList (`type: MANGA`): Trending manga, Popular manhwa (KR),
Popular manhua (CN), genres. Books rows from Open Library (trending, subjects).
Card -> Download = follow in Suwayomi (whole series or from chapter N) / grab
the book. "Reading" row = Continue reading from Jellyfin UserData.

## Also from issue #8

- **Light novels and comics** too: novels as EPUB through the book path
  (Prowlarr), western comics as CBZ/CBR through the comic path.
- **Completed list**: a series/book read to the end goes to My List >
  Completed (reuses completed.rs, per profile).
- **Clean-up of read chapters**: Settings > Library & storage, "Delete
  chapters after reading" (off / 1 day / 3 days), only chapters every profile
  has read; Suwayomi is told so it doesn't fetch them again.
- **Speed**: page route streams the zip entry without unpacking the archive;
  manifest cached by file mtime; bench in `read.rs` tests.
